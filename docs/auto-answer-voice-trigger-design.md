# 自动答题 / 语音触发设计

> 最后更新：2026-06-14。

## 目标

在现有「系统音频持续收题 + 当前问题回答」流程上叠加自动触发模式：开启后，根据系统音频转写的静默间隔自动回答当前累计问题。

## 当前缺口

手动流程依赖用户点击主按钮或按确认热键。面试官停顿时如果用户没有触发，当前题不会自动提交，长面试中仍需要频繁手动操作。

## 锁定决策

- 新增配置 `autoAnswer: boolean`，默认 `false`。
- 不改音频采集、ASR、系统音频收题拼接逻辑。
- 静默检测只基于系统音频转写事件：每收到一条有效系统音频转写后重置定时器。
- 收集中且当前问题非空时，静默 `1600ms` 自动回答当前问题。
- 自动回答与手动按钮、确认热键复用同一条渲染层入口：快答和深答同时启动，问题缓冲立即清空并继续收音。

## 非目标

- 不新增 VAD、音频能量检测或 ASR 拼接策略。
- 不改变系统音频和麦克风双流职责。
- 不新增主进程 IPC 或协议。

## 状态与配置影响

- `AppConfig` 增加 `autoAnswer`。
- `defaultConfig` 默认关闭。
- `configStore` 的 zod schema 必须包含该字段，避免 `.parse()` strip 未知字段导致配置丢失。
- 渲染层用 ref 同步配置开关，避免系统音频监听回调读取过期闭包。

## 验收标准

- 关闭自动答题时，手动按钮和确认热键行为保持一致。
- 开启自动答题时，系统音频转写停止约 1.6 秒后自动提交当前问题，同时出快答和深答。
- 回答后清空问题缓冲，后续系统音频继续累积下一题。
- 清空本轮和组件卸载时清理 timeout。
- `npx tsc -p tsconfig.node.json --noEmit`、`npx tsc -p tsconfig.json --noEmit`、`npm test` 通过。
